# Seedcore — 설계 문서

레포: https://github.com/kws0109/seedcore · 플레이: https://kws0109.github.io/seedcore/

작성일: 2026-07-31 · 상태: 승인 완료 · 목표 완성일: 2026-08-10

## 1. 컨셉

던전을 클리어하면 그 던전을 **코어**로 응축해 사고팔 수 있는 탑다운 핵앤슬래시.
코어는 시드가 보존된 던전의 녹화본이다. 코어를 사용한 사람은 판매자가 겪은
배치·몬스터·득템 순간을 그대로 경험한다.

차별점: 기존 핵앤슬래시(POE·디아블로)의 RNG 파밍 대신, **"원하는 아이템이 확정으로
든 던전을 골라 산다."** 던전의 총 전리품이 시드에 고정되기 때문에 가능한 구조.

## 2. 코어 게임 루프

1. 던전 진입 → WASD 액션으로 클리어 (1런 2~3분)
2. 루팅 → 골드 + 장비 드롭 (드롭은 던전 시드에 고정 = 확정 드롭)
3. 코어화(선택) → 클리어한 던전을 코어로 변환
4. 코어 사용처:
   - **NPC 시장에 판매** → 골드
   - **시드 코드로 외부 공유** → 타인이 내 던전을 그대로 플레이
   - 직접 재사용 불가. **코어는 1회 소모품이며, 코어로 연 던전은 재코어화 불가** (복제 차단)
5. NPC 시장에서 코어 구매 → 상점에 각 코어의 **확정 드롭 목록이 공개**됨
6. 골드로 스탯 성장 → 더 위험한 던전으로

## 3. 전투

- WASD 이동 + 마우스 방향 근접 슬래시(호 형태) + 스페이스 대시(무적 프레임)
- 몬스터 3종: 추적 근접형 / 원거리 투사체형 / 느리고 단단한 엘리트형
- 시점: 수직에 가까운 탑다운 (Hero Siege식). 연출은 Hades식: 히트스톱, 파티클,
  화면 흔들림, 대시 잔상, 발광 이펙트
- 보스 1종(패턴 2개짜리 대형 엘리트)은 **스트레치 골** — 일정 여유 시에만

## 4. 던전 생성과 시드 (기술적 핵심)

- 시드 하나에서 방 배치·몬스터 스폰·드롭이 전부 결정되는 **완전 결정론적 생성**
- 코어 = `시드 + 난이도 + 확정 드롭 요약 + 체크섬`을 인코딩한 짧은 문자열
  - 이 문자열이 곧 공유 코드이자 거래 아이템. 서버 불필요
  - 잘못된 코드는 체크섬으로 거부
- 결정론이 깨지면 컨셉 전체가 깨진다 → **시드 재현성을 유닛 테스트로 보증**

## 5. 성장 (최소 범위)

- 장비: 무기 보정치 + 방어구, 희귀도 3단계. 인벤토리는 단순 목록
- 골드 사용처: 스탯 업그레이드(공격력/체력/이동속도) + 시장 코어 구매
- 컷: 스킬트리, 물약, 소모품, 캐릭터 클래스

## 6. 기술 스택과 아키텍처

- **PixiJS v8 + TypeScript + Vite**, GitHub Pages 배포 (버전 고정)
- **로직/렌더 분리**: 게임 로직은 순수 TS(렌더러 무관, 고정 타임스텝, 시드 RNG),
  렌더링만 Pixi. 결정론 테스트가 렌더러 없이 돌아간다
- 자작 엔진 범위: 게임 루프, 입력, 원/AABB 충돌, 카메라(추적+흔들림), 파티클, 트윈
- 메타 UI(시장·인벤토리·코어 코드 입출력)는 **HTML/CSS 오버레이**
- 비주얼: **중세 다크판타지** (2026-08-01 체크포인트에서 네온 미니멀 방향을 폐기하고 전환).
  - 스프라이트: 이미지 생성 AI 파이프라인(`tools/gen-assets.mjs` + `assets/manifest.json`)으로
    제작. 스타일 템플릿 프롬프트를 전 에셋에 접두해 일관성 강제. 정적 스프라이트 + 코드 모션
    (기울임·바운스·플래시·무기 궤적 이펙트) 문법 — 애니메이션 프레임을 그리지 않는다.
  - 분위기는 코드 연출: 횃불 광원 웅덩이, 어둠 비네트, 안개, 채도 낮춘 팔레트.
  - 후퇴선: 이미지 에셋 품질·일관성이 확보되지 않으면 코드 실루엣 아트로 전환.
- 저장: localStorage. 몬스터·장비·던전 파라미터는 JSON 데이터 테이블로 분리
- 릴리즈는 태그로 빌드 동결, 이후 개발은 별도 브랜치

## 7. 테스트 전략

- 유닛 테스트: 시드 결정론(같은 시드 → 같은 던전·드롭), 코어 코드 인코딩/디코딩
  왕복, 손상된 코드 거부
- 수동 QA: 신규 플레이어 첫 5분 동선 기준 체크리스트 — QA 경력 기반으로 직접 설계

## 8. 일정 골격 (8/10 데드라인)

| 일차 | 작업 |
|---|---|
| D1~2 | 이동·전투 프로토타입 → **아트 방향 재정리 체크포인트** |
| D3~4 | 던전 생성 + 몬스터 3종 + 루팅 |
| D5~6 | 코어 시스템 + NPC 시장 + 성장 |
| D7 | 타격감 폴리싱 |
| D8 | QA·버퍼 |
| D9 | 플레이 영상 + 소개 문서 |
| D10 | 릴리즈 |

- `docs/ai-usage-log.md`를 D1부터 매일 누적 (AI 활용 내역의 기록)
- 외부 에셋(사운드 포함) 사용 시 출처·라이선스를 같은 로그에 즉시 기록

## 9. 결정 이력 (요약)

- 접근안 A 채택: 코어 루프 집중 + 다크 네온 폴리싱. 완성일은 하드 데드라인
- 시점: Hades식 쿼터뷰 배제(코드 아트와 부적합), Hero Siege식 탑다운 채택
- 스택: Unity·Godot 웹 빌드 배제(Pages 헤더·빌드 크기·AI 반복 속도),
  Phaser 검토 후 PixiJS + 자작 엔진 확정(제로 코드 조건에서 디버깅 투명성·결정론 우선)
