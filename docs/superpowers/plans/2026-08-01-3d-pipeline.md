# Seedcore 3D 애니메이션 파이프라인 Implementation Plan (진행 중)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 파일럿 검증 중인 계획 — 아래 "현재 상태"부터 읽을 것.

**Goal:** 스프라이트를 레퍼런스로 3D 모델+리깅+애니메이션을 생성하고, 4방향 스프라이트 시트로 사전 렌더링해 게임에 프레임 애니메이션을 넣는다.

**Architecture:** Meshy API(이미지→3D→리메시→리깅→애니메이션 클립) → three.js 캡처 페이지(고정 3/4 카메라, Playwright 무인 캡처) → Pixi AnimatedSprite. **무기는 리깅에서 분리**해 별도 정적 메시로 손 본에 부착하고, 캐릭터/무기를 별도 패스로 캡처해 게임에서 레이어 합성 — 아이템 시스템이 붙으면 무기 GLB만 교체하고 무기 패스만 재캡처한다.

**도구:**
- `tools/gen-3d.mjs` — Meshy 파이프라인 (태스크 캐시로 재실행 시 완료 단계 스킵, `norig` 모드 = 정적 메시)
- `tools/preview3d.html` — three.js 뷰어/캡처 (`?glb=&weapon=`, `__snap`, `__captureClip`, `__bones`, `__weaponGrip`)
- 산출물: `assets/3d/*.glb` (gitignore — tasks.json의 태스크 ID로 재다운로드 가능)

## 현재 상태 (2026-08-01 종료 시점)

**완료:**
- 기사(player-knight-rig): 검 없는 클린 레퍼런스로 재생성 → 리깅 → 클립 4종(idle/walk/walk2/attack)
- 검(weapon-longsword): 정적 메시. RightHand 본 부착 + 본 월드 스케일 역보정 검증
- 통과: 검 강직 ✓ / 망토-손 분리 ✓ / 걸음 자연스러움 ✓
- 교훈: 이미지 편집 API로 원본에서 요소 제거는 원본이 뭉개짐(2회 실패) → 신규 생성이 정답

**사용자 리포트 이슈 (내일 최우선):**
1. **검이 손바닥이 아니라 손목에 붙음 + 검날이 아래를 향해 캐릭터 메쉬 관통.**
   → 그립 그룹을 본 원점(손목 관절)에서 손바닥 방향으로 오프셋하고(본 로컬 축 확인 필요),
   그립 회전을 재튜닝. `__weaponGrip`으로 브라우저에서 실시간 조정 후 상수 확정.
   클립별(특히 attack) 별도 각도 필요 여부 확인.
2. **망토가 팔을 들 때 몸을 관통하며 앞으로 나옴.** Meshy 자동 리깅은 망토 본을 추가하지
   않음. 내일 검토 순서: (a) 게임 표시 크기(64px) 캡처에서 실제로 보이는지 먼저 확인 —
   안 보이면 수용, (b) 보이면 망토 없는 모델 재생성 + 망토를 별도 레이어(무기와 같은
   분리 패스) 또는 2D 연출로, (c) 사전 렌더 단계의 간이 클로스 시뮬은 비용 대비 후순위.

**대기 중 (그립·망토 해결 후):**
- 캡처 자동화 스크립트 (캐릭터/무기 분리 패스, 4방향×클립 프레임, rAF 정지 플래그 필요 — __snap 직후 rAF가 덮어쓰는 문제 확인됨)
- 스프라이트 시트 팩 + Pixi AnimatedSprite 통합 (방향=각도, 상태=대기/걷기/공격)
- 몬스터 3종 확장 (~150크레딧, 사용자 승인 후). 구울 체형의 휴머노이드 리깅 실패 가능성 → 실패 시 해당 몬스터만 기존 방식 유지
- 텍스처 톤(청동·녹청 → 원본 어두운 강철) 재생성 여부는 사용자 판정 대기

**크레딧 소모 누적:** 약 140~190 (기사 1차 50 + 검 35 + 기사 2차 52 + 모델 생성분)
